How to use the binary calculator

For arithmetic, enter a binary number in each of the two value fields, select +, −, ×, or ÷, and calculate. For conversion, use the separate Binary Value → Decimal Value or Decimal Value → Binary Value field. The three functions are distinct: converting a number changes its notation, while arithmetic changes its value.

Enter binary digits using only 0 and 1 unless the tool explicitly accepts another format. For decimal-to-binary conversion, enter a base-10 number. If a result looks surprising, verify the number base and whether any leading zeros are simply padding.

What a binary number means

Binary is a positional number system with base 2. It has only two digits, 0 and 1, called bits. In decimal, each place is worth ten times the place to its right; in binary, it is worth twice as much. Counting from the rightmost whole-number bit, the place values are 2⁰ = 1, 2¹ = 2, 2² = 4, 2³ = 8, 2⁴ = 16, and so on.

Binary is particularly practical in digital hardware because circuits can distinguish two logical states reliably. A bit records one binary digit; eight bits make one byte. Those bit patterns can represent numbers, text, images, or machine instructions depending on how software interprets them.

A whole binary number bₙ…b₂b₁b₀ represents bₙ × 2ⁿ + … + b₂ × 2² + b₁ × 2¹ + b₀ × 2⁰, where each b is 0 or 1. For example, 101101₂ means 32 + 8 + 4 + 1 = 45₁₀. Subscripts identify the base: 10₂ means two, whereas 10₁₀ means ten.

Convert binary to decimal

To convert a binary integer to decimal, write the powers of 2 above its positions, multiply each power by its bit, and add the contributions. Zeros contribute zero, but their positions still matter.

Worked example: 110101₂ = (1 × 32) + (1 × 16) + (0 × 8) + (1 × 4) + (0 × 2) + (1 × 1) = 53₁₀.

You can also evaluate bits left to right: begin at 0, then repeatedly double the running total and add the next bit. For 110101₂, the running totals are 1, 3, 6, 13, 26, and 53. This is the same place-value calculation performed without writing every power.

Convert decimal to binary

One direct method is to find the largest power of 2 no greater than your decimal integer, subtract it, and repeat with the remainder. Put 1 in every power-of-2 position used and 0 in the positions skipped.

Worked example: 42₁₀ = 32 + 8 + 2 = 2⁵ + 2³ + 2¹, so the bits in positions 5 through 0 are 1 0 1 0 1 0. Therefore, 42₁₀ = 101010₂.

An alternative is repeated division by 2. Divide 42 by 2 and record remainder 0; then divide the quotient 21 and record remainder 1; continue with 10 → 0, 5 → 1, 2 → 0, and 1 → 1. Read the remainders from last to first to obtain 101010₂. The reversal matters because the first remainder is the least significant bit.

For zero, the binary representation is 0. Both methods above describe nonnegative whole numbers; fractional or signed representations need additional conventions.

Binary addition

Add bits from right to left, just as with decimal columns. When a column totals 2 (10₂), write 0 and carry 1 into the next column. A column containing two 1s plus a carried 1 totals 3 (11₂): write 1 and carry 1.

Worked example: 10111₂ + 01101₂ = 100100₂. From right to left, the first two columns each write 0 and carry 1; the next column sums 1 + 1 + 1 = 3, so it writes 1 and carries again. Continue to the left and include the final carry as the new highest bit.

Decimal check: 10111₂ is 23, 01101₂ is 13, and 23 + 13 = 36 = 100100₂.

Binary subtraction

Subtract from right to left. The basic cases are 0 − 0 = 0, 1 − 0 = 1, and 1 − 1 = 0. If a column requires 0 − 1, borrow from the next nonzero bit to the left. A borrowed 1 from the adjacent place is worth 2 in the current place, so the column becomes 2 − 1 = 1. If intermediate bits are zero, the borrow passes through them.

Worked example: 10010₂ − 01011₂ = 00111₂. At the right edge, 0 − 1 requires a borrow from the 2s column. Working left, later columns also require borrowing across the zeros until the subtraction is complete. The result 00111₂ is 7₁₀, consistent with 18 − 11 = 7.

Leading zeros can be retained for column alignment during a worked problem; removing them does not change the value. A negative result needs a signed-number convention, which is separate from ordinary unsigned column subtraction.

Binary multiplication

Multiply by each bit of the second number, starting on the right. Multiplication by 0 produces a row of zeros; multiplication by 1 reproduces the first number. Shift each successive partial product one position left, equivalent to multiplying by 2, and add the rows.

Worked example: 1011₂ × 101₂. The rightmost multiplier bit contributes 1011₂; the middle 0 contributes nothing; the leftmost 1 contributes 101100₂ (1011 shifted two places). Adding 001011₂ + 101100₂ gives 110111₂.

Decimal check: 11 × 5 = 55, and 110111₂ = 55₁₀. Do not discard a trailing zero in a shifted row: unlike an optional leading zero, a trailing zero changes the place value.

Binary division

Binary long division is a repeated compare–subtract–bring-down process. A quotient bit is 1 when the current partial dividend is at least the divisor; subtract the divisor, then bring down the next bit. Otherwise, the quotient bit is 0, and you bring down the next bit without subtracting. Continue until all dividend bits have been processed.

Worked example: 101101₂ ÷ 11₂ = 1111₂ with remainder 0. After the first usable group 101₂, subtract 011₂ to leave 010₂. Bring down successive bits 1, 0, and 1; the new partial values are 101₂, 100₂, and 011₂, each large enough to subtract 011₂. This produces four quotient bits of 1 and a final remainder of zero.

Not every division is exact. For example, 11010₂ ÷ 100₂ is 110₂ with remainder 10₂, since 26 = (4 × 6) + 2. A different calculator may express the same value as the binary fraction 110.1₂ instead of showing an integer quotient and remainder separately. Check the displayed result convention.

Division by 0 is undefined. If the divisor is 1₂, the quotient equals the dividend and the remainder is zero.

Understand the result and avoid common errors

Watch the number base. The text 1000 means eight in binary, not one thousand. Include the carry at the far left when addition creates another bit, and keep zeros inserted by multiplication shifts or by skipped place values.

Leading zeros do not change an unsigned integer: 001011₂ and 1011₂ both represent 11. Trailing zeros do change it: 10110₂ is 22, not 11. This difference is especially important in multiplication and place-value conversion.

A fixed-width computer representation can overflow even when ordinary arithmetic has a valid answer. For example, 1111₂ + 1₂ = 10000₂ requires five bits; storing only the lowest four bits would leave 0000₂. The arithmetic calculator on this page should not be assumed to use a particular bit width unless its interface specifies one.

What about negative numbers and binary fractions?

A minus sign and a bit pattern are not automatically the same thing. Computers commonly use fixed-width two’s complement for signed integers: in 8 bits, −5 is represented by 11111011, while the identical bits read as an unsigned number represent 251. The width and signedness must be known before interpreting such a bit string. This is background context, not a claim that every calculator input accepts two’s-complement notation.

Binary fractions place powers of two to the right of the point: 0.1₂ is one-half, and 10.1₂ is 2.5₁₀. Whether a particular calculator accepts fractional input or reports fractional quotients depends on its input rules; the whole-number methods above do not require fractional support.
