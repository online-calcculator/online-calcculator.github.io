How to Use the IP Subnet Calculator

This calculator divides an IPv4 or IPv6 address space into its network and host portions. Select the subnet mask or prefix, enter an IP address, and choose Calculate. The results appear immediately above that version’s form, without leaving the page.

  1. For IPv4, choose Any, A, B, or C to filter traditional mask ranges. Select a dotted-decimal subnet mask and enter an IPv4 address.
  2. For IPv6, select a prefix length from /1 through /128 and enter an IPv6 address, including valid :: compression if desired.
  3. Review the network address, address range and counts. The IPv4 tool also lists every same-sized subnet inside the relevant /8, /16, or /24 parent block. Use Save or the CSV action to export results.

You can also type a CIDR suffix directly into either address field (for example, 192.168.10.37/26 or 2001:db8::1/64); that prefix takes precedence over the dropdown, provided it is allowed by the current selector.

IPv4 Subnet Formulas

An IPv4 address has 32 bits. A prefix /p identifies the first p bits as network bits and leaves 32 − p bits for host addressing.

  • Subnet mask: p leading binary ones followed by 32 − p zeros.
  • Network address: IP address AND subnet mask.
  • Broadcast address: network address OR inverse (wildcard) mask.
  • Total addresses: 232 − p.
  • Conventional usable hosts: 232 − p − 2 for prefixes /1 through /30.

Worked IPv4 Example

For 192.168.1.129/26, the subnet mask is 255.255.255.192. A /26 block contains 64 addresses; the network is 192.168.1.128, its broadcast address is 192.168.1.191, and the conventional usable range is 192.168.1.129 through 192.168.1.190 (62 hosts).

Special Cases: /31 and /32

To match the reference calculator's traditional subnet table, the primary IPv4 usable-host count is shown as zero for /31 and /32. Modern routing has exceptions: under RFC 3021, both /31 addresses are usable endpoints on a point-to-point link; a /32 describes one individual host route. The detailed output identifies these cases separately.

IPv6 Prefixes and Address Ranges

IPv6 uses 128-bit addresses and a routing prefix, not an IPv4-style broadcast address. For an IPv6 /64, the range contains 264 = 18,446,744,073,709,551,616 addresses. The tool uses exact integer arithmetic, expands addresses into eight four-character hexadecimal groups, and compresses consecutive zero groups following RFC 5952 conventions.

For example, 2001:db8:85a3::8a2e:370:7334/64 belongs to 2001:db8:85a3::/64. Its first address is 2001:db8:85a3::, and its last address is 2001:db8:85a3:0:ffff:ffff:ffff:ffff. Unlike IPv4, no network or broadcast address is subtracted from the IPv6 count.

Frequently Asked Questions

What is the difference between a subnet mask and CIDR notation?

They express the same IPv4 network boundary in different formats. A dotted mask of 255.255.255.0 is equivalent to /24.

Does choosing class A, B, or C change the entered IP address?

No. These options filter the subnet dropdown to prefixes /8 and longer, /16 and longer, or /24 and longer. Modern CIDR routing is classless, so an address's historical class does not dictate its actual network prefix.

Why are subnet boundaries different from the entered IP address?

The network address is calculated by clearing all host bits. An address such as 192.168.1.129/26 is inside the 192.168.1.128/26 subnet.

Does this tool support IPv6 compressed addresses?

Yes. IPv6 inputs may contain :: once to replace consecutive zero groups. Expanded and compressed results are both available.

Are the calculations sent to another website?

No. All parsing, subnet calculations and table generation occur locally in your browser, with no server-side submission.
